TRSToolGui — Changelog
======================

v1.8 — November 24, 2026
  Disk > Import from another image copies files straight out of another floppy, hard disk,
    cassette or WAV image onto the open one. It needs trs80-tool 5.3.0, which added the
    command this is built on; with an older trs80-tool the menu item is greyed out. This is
    worth having over Copy and Paste because trs80-tool does the copying rather than the
    program: each file arrives with its own date and its system and hidden attributes, and a
    BASIC program is converted between Model III and Model 4 tokens when the two disks run
    different BASICs. Copy and Paste, and dragging between two windows, write the file out to
    a temporary Windows file and add it back, which keeps none of that. Either every file is
    copied or none is, unless you leave "Skip a file that can't be copied" on, which is the
    default. Preview runs the same command as a dry run: it writes nothing and prints what it
    would copy, rename and skip.
  Adding several files no longer fails as a whole because of one of them. With trs80-tool
    5.3.0 a file that cannot be added — no room for it, or a name already on the disk that you
    chose not to replace — is skipped and the rest still go in, and the program then says how
    many were added and why each of the others was left out. With an older trs80-tool it
    behaves as before: one file that will not fit means nothing is written.
  trs80-tool 5.3.0 is the version this release was built against. Two of its changes needed
    nothing here and are worth knowing about anyway: wildcards now follow the same DOS rules
    on Windows files as on files on a disk, so a name written the way the archive writes them,
    with brackets in it, is matched as the plain name it is; and trs80-tool will not add a disk
    image to itself even when a wildcard picks it up.
  The French is unchanged except for the new window and its messages, which have had no
    reviewer yet. Corrections are welcome as issues at the address under Help.

v1.7.1 — November 24, 2026
  Opening a disk image from the Finder works. In v1.7 it did not: double-clicking an image
    answered "TRSToolGui cannot open files in the TRS-80 floppy disk image format". That is
    macOS's own message, not the program's, and it is the proof that the file types v1.7
    declared are right, because the wording inside the quotation marks is taken from the
    declaration itself. What was wrong was the moment the program began listening. macOS puts
    in its own handler for the open-document event inside the step that finishes launching an
    application, so anything a program registers before that is thrown away a moment later.
    The program now registers again at the one point where it survives, when the system says
    it is about to finish launching, and keeps the earlier registration for the case where
    the program is already running and the Finder sends the event to it. Which registration
    took effect is written to TRSToolGui-open.log beside TRSToolGui.cfg.
  Nothing else is changed. The Windows and Linux programs are v1.7 built again under the new
    version number.

v1.7 — November 24, 2026
  The program has an icon of its own, a TRS-80 diskette, in place of the blank sheet Windows
    gives a program that brings none. Windows shows it on the file, on a shortcut and in the
    Start menu, and every window of the program now carries it in its title bar and on the task
    bar button. The Mac application takes the same picture, in place of the drawn diskette of
    v1.4, and the Linux window asks for it too.
  On a Mac you can open a disk image from the Finder. Double-click a .dmk, .jv1, .jv3, .dsk,
    .hfe, .imd or .scp file once TRSToolGui is the program it opens with, and the image opens in
    the window; before this the Finder answered "TRSToolGui cannot open files of this type" and
    there was nothing to be done about it. Two things were missing and both are in: the bundle
    now tells macOS which kinds of file the program handles, and the program now listens for the
    open-document event the Finder sends, which is the only way a Mac passes a file to a program
    that is already running. Cassette images, .cas and .wav, are deliberately not claimed: the
    program opens them when you ask it to, but it does not put itself forward as the program
    that owns them.
  Every open-document event a Mac sends is written to TRSToolGui-open.log, beside
    TRSToolGui.cfg, whether or not the image then opens. If opening from the Finder does not
    work for you, that file says how far it got and is worth attaching to a report.
  Nothing else is changed in the Windows, Linux and Mac programs.

v1.6 — November 23, 2026
  The program's own text can be French. Preferences has a Language list with English and
    Francais in it; the choice takes effect the next time the program starts. A new installation
    starts in English and stays there until you pick something else, whatever the system's own
    language is set to.
  One table of text serves all three programs, so the Windows, Linux and Mac versions are
    translated by this one release.
  What stays in English whichever language you pick: the DMK analysis and the other disk
    analysis reports, which are forensic notes full of names that must not be translated;
    anything trs80-tool itself prints; the manual; and this changelog.
  Every window was taught to make room for longer words. A label that reaches the box beside it
    pushes the box along, a note that no longer fits on one line gets another, a button grows to
    its text, and a column widens to its heading. In English none of it moves: the text is the
    text each window was drawn around. The one deliberate exception is the sector map's Close
    button, which used to sit sixteen pixels past the right edge of the window and was clipped.
    It is now inside the window.
  Two keyboard letters in the English menus changed, because each of them answered to two items
    and had since v1.0. Edit > Add files... is now Alt+D, so that Select all keeps Alt+A as it
    does in every Windows program; and the file list's right-click Rename... is now Alt+M, the
    letter Explorer uses, so that Properties keeps Alt+R.
  Help > Report a problem (web) opens the issues page, where every report belongs.
  The French is a first translation and has not been through a reviewer who knows both the
    language and TRS-80 floppies. A word that reads wrongly is worth an issue.
  Nothing else is changed in the Windows, Linux and Mac programs.

v1.5 — November 22, 2026
  DMK analysis: on a NEWDOS/80 disk the Summary now has "PDRIVE from the media", the PDRIVE
    settings worked out from the disk itself (density, sides, sectors, directory and GAT)
    rather than from the drive table FORMAT left on it, so a disk without a table gets them too.
    There is one line for each machine and interface that can read the disk, and the
    identification notes compare them with the boot sector's bytes and the drive table.
  Mac: the manual and the README no longer say to run "chmod +x" on trs80-tool. Its download
    is a zip now, and the program comes out of the zip ready to run. Only its quarantine has to
    be removed, with "xattr -d com.apple.quarantine trs80-tool".
  Nothing else is changed in the Windows, Linux and Mac programs.

v1.4 — November 18, 2026
  TRSToolGui for the Mac. This is the first Mac build, and when it was made it had not been run
    on a Mac: it is the Linux program's source, built on Windows for macOS. Please report what
    works and what doesn't at https://github.com/jdmba/TRSToolGui/issues.
  Two downloads, each holding TRSToolGui.app: TRSToolGui-v1.4-macos-arm64.zip for a Mac with
    Apple Silicon (M1 and later) and TRSToolGui-v1.4-macos-x64.zip for a Mac with an Intel
    processor. It needs macOS 14 or later and the Mac trs80-tool.
  The app is not signed with an Apple developer certificate, so macOS has to be told once to
    open it. The manual's new section ON THE MAC has the steps and everything that differs.
  On a Mac the menus are where Mac programs have them. About, Preferences and Quit are in the
    TRSToolGui menu. Edit has the Mac's own Cut, Copy, Paste, Delete and Select All, which work
    on text in a text box and on the file list when the list has the focus. There is a Window
    menu, and shortcuts use Cmd.
  On a Mac trs80-tool is looked for where Preferences says, in the folder TRSToolGui.app is in,
    on the PATH, and in /opt/homebrew/bin, /usr/local/bin, ~/bin and ~/.local/bin. The settings
    are in ~/Library/Application Support/TRSToolGui/TRSToolGui.cfg.
  Linux: File > Open Recent and View > Partition showed every underscore of a name twice
    (my__disk.dmk for my_disk.dmk). Fixed. A name with an ampersand in it is shown whole.
  Apart from that the Windows and Linux programs are unchanged but for the version number.

v1.3 — November 18, 2026
  TRSToolGui for Linux (x64). This is the first Linux release: the same program, with its
    windows rebuilt on Eto.Forms (GTK 3 underneath). All of it is there: the main window, the
    viewer, Disk properties, File properties, the sector map, the granule map, the DMK analysis,
    Check & repair, Format, Trim, the hard disk dialogs, the CP/M layout, Convert, Assemble,
    Preferences and the report windows.
  It is a download of its own, TRSToolGui-v1.3-linux-x64.zip. Unzip it, make the file runnable
    once with "chmod +x TRSToolGui", and run it. It needs GTK 3, which desktop Linux has, and
    the Linux trs80-tool, which it finds beside itself, on the PATH, or where Preferences says.
  On Linux the settings are in ~/.config/TRSToolGui/TRSToolGui.cfg, text is extracted with LF
    line ends unless Preferences says otherwise, and the trs80-tool shell and the emulator open
    in a terminal window (Preferences can name the terminal).
  Not in the Linux program: dragging files out of the list to a file manager. Copy and Extract
    do that job. Dropping files onto the list, and Paste, are there.
  The manual has a new section, ON LINUX, with everything that differs.
  The Windows program is unchanged apart from its version number.

v1.2 — November 16, 2026
  Tested with trs80-tool 5.2.0. Still needs 5.1.0 or later; what 5.2.0 adds is offered when the
    installed trs80-tool is 5.2.0.
  CP/M disks (trs80-tool 5.2.0 writes Montezuma Micro CP/M and the other CP/M layouts it knows):
    Add, Delete and Rename work on them. The status bar and Disk properties show their free
    space in CP/M blocks. File properties sets Read-only (R/O) and System (SYS). File > New and
    Disk > Format make Montezuma CP/M data disks (40 or 80 tracks, 1 or 2 sides), and File > New
    makes the CP/M 2.32 system disk.
  Disk > CP/M layout (trs80-tool 5.2.0): when trs80-tool picks the wrong layout for a CP/M
    floppy, name the right one from its list. The disk is then read and written that way.
  Gzipped images: File > Open lists and opens GAME.DMK.GZ, BIG.HDV.GZ and the like, and every
    window works on them, the DMK analysis included. A new image saved under a .dmk.gz name is
    written compressed.
  Adding a file named *.gz: trs80-tool 5.2.0 unzips such a file and stores what is inside.
    TRSToolGui keeps storing the .gz file as it is, as TRSTools did. A new Preferences box,
    "Unzip files named *.gz when adding them", turns the unzipping on; the name, the text test
    and the conversions are then those of the file inside.
  Disk > Granule map also draws the open partition of a hard disk (trs80-tool 5.2.0). The row
    header says Cylinder where the DOS's lumps are cylinders.
  Disk > DMK analysis and Disk properties ("From the bytes"), MultiDOS: brought in line with what
    Vernon Hester, the author of MultiDOS, has said about his formats. A bare disk formatted by
    MultiDOS 4.01 or later is recognized whatever date was set when it was formatted (DIR/SYS
    holds that date; only an undated format has A8 00 00 00), and the date is shown. Boot byte FA,
    which seemed to split 4.01/5.00 from 5.10 and later, is the cylinder the drive's head was on,
    so that split is now given as unverified. From 2.1 on the four DIR/SYS bytes are read and
    shown as a date stamp (the release date on a system disk), no longer called a password.
  trs80-tool is also looked for in TRSToolGui's own folder and on the PATH before the program
    asks where it is.
  Help > About gives the download as https://github.com/jdmba/TRSToolGui.
  Source: everything that is not a window (the trs80-tool adapter, the disk model, the DMK and
    assembler-source analysis, the settings) is now a library of its own, TRSToolGui.Core, in
    the Core folder. It uses no Windows-only code and builds on Windows, Linux and macOS. The
    Windows program is built from the same code and works as before.

v1.1 — November 12, 2026
  Needs trs80-tool 5.1.0 or later. An older trs80-tool is refused at startup with a message that
    says where to get the current one.
  Faster. One trs80-tool is kept running in the background and answers every disk question,
    instead of the program being started for each one (Preferences: "Keep trs80-tool running in
    the background"; if it ever misbehaves the GUI goes back to one start per action by itself).
    Opening an image now takes three questions instead of six.
  Everything about a disk is now read as data from trs80-tool ("disk --json", "help --json"); none
    of its printed text is interpreted any more. What trs80-tool can do is asked of it at startup.
  More disks can be changed: trs80-tool 5.1.0 writes TRSDOS 2.7 and 2.8, NEWDOS/80 and MultiDOS 1.x
    and 2.00 disks, so Add, Delete, Rename and Properties work on them.
  File > New hard disk image: makes an HDV hard disk, blank or with LDOS 5.3 or LS-DOS 6.3
    partitions. View > Partition > Add a partition / Delete this partition.
  Disk > Granule map is now a coloured grid of every granule (which file, free, directory, locked
    out, damage), with the list of files beside it. trs80-tool's own text drawing is one button away.
  Disk > Sector map: "Protection & artifacts" lists trs80-tool's signs of copy protection, with
    the trs-80.com scheme numbers, and the bad sectors that the imaging likely caused. Bad sectors
    that an imaging artifact explains say so.
  Disk properties: a "Copy protection" line and an "Imaging artifacts" line; free space counts
    apart the granules that new files can't use; "Damaged" comes from trs80-tool's check.
  NEWDOS/80 PDRIVE now comes from trs80-tool, which reads TI, TSR and the I/J/K flags from the
    disk's own drive table (and says so when a disk has no table and the line is worked out from
    its layout). The GUI's own calculation is gone from Disk properties.
  File list: the Attributes column shows C (created) and * (modified since backup) on LDOS,
    TRSDOS 6 and LS-DOS 6 disks, as TRSTools did.
  File properties: shows whether a file has an update and an access password (none, PASSWORD, or
    set), and the Created and MOD bits. "Set access password" is disabled where trs80-tool says
    the disk keeps a time stamp there (LDOS 5.3, LS-DOS 6.3).
  Master passwords: PASSWORD and blank are recognized on every DOS, including TRSDOS 1.x, SuperDOS,
    DOS500 and RAPIDOS, which hash them differently.
  Adding files: "Convert CR/LF to CR" still looks at the file's contents, as TRSTools did, and now
    has trs80-tool do the conversion ("add --text"). Files with the same options are added in one
    step, which is much quicker on large disks.
  Check & repair: new option "mark used the free granules the image doesn't fully hold"
    (--mark-missing-used). The check also lists signs of copy protection and imaging artifacts;
    trs80-tool refuses to repair or trim a disk that shows signs of copy protection.
  File viewer: hi-res pictures (HR, HRG, HRX, CHR, SHR) are drawn by trs80-tool, in the right
    proportions, and Save as writes its PNG. Tools > Convert file(s) makes PNGs of them too.
  Error messages: trs80-tool now says why something failed (not found, read-only, write-protected,
    damaged, disk full) and the GUI shows its sentence; when trs80-tool fails unexpectedly, only
    its message is shown, not the stack trace.
  Help > Engine capabilities lists the DOSes and image formats the installed trs80-tool handles and
    the options of each command.
